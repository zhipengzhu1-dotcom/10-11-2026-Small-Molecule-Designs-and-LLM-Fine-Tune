# Context

Replicating s1 (arXiv 2501.19393) at small scale. Spec: GitHub issue #1.

## Factory logs

- **Event**: one JSON line with `ts`, `run`, `agent`, `type` and the type's required fields (issue #1). Written only through `factory/log.mjs`, which stamps `ts`, `run` and `agent`.
- **Activity file**: `factory/agents/<run-id>/<agent-id>.jsonl`. One per agent; an agent writes only its own. Committed.
- **Decision log**: `factory/decisions.tsv`, pstack show-me-your-work format, append-only, written only by the orchestrator, one row per `npm run decide -- <phase> <decision> <why> <evidence> <result>`. That runs the installed pstack's `log.sh` (found through `installPath`, never a cache path) and puts the session transcript pointer first in the evidence. Committed. In the stream its rows are `type: "decision"` events with `agent: "orchestrator"` and `run: null`. This is deliberate (issue #21): the TSV has no run column, and the run marker can't stand in for one, because it is local state that each run overwrites. Decision events are the only events with a null run; a reader places them in a run by `ts`.
- **Event stream**: `readStream()` in `factory/read.mjs`. Merges every activity file and the decision log by `ts`. Tests and the dashboard read only this. It throws on a corrupt line or an event filed under the wrong agent or run.
- **Audit**: `factory/audit/<run-id>.tsv`, one verdict (`ok` or `superseded`) per decision-log row, with the pointers the auditor checked. Written by the run that audited the log against the transcripts (pstack show-me-your-work). The auditor reads a transcript through `factory/transcript.mjs` (`npm run transcript -- <session-id>` prints one timestamped line per message and tool call), not a parser of its own. A wrong row is never edited: a later row supersedes it, and the audit names that row's line.
- **Trail review**: `factory/audit/<run-id>.review.md`, the cross-family model's review of the trail, made with `npm run review:qwen -- <prompt> <files>... --out <it>` (local `qwen3.5:9b`, thinking off in code). Its `reviewed by <model>` line names the reviewer. Its flags go in the Attention section of the run's final reply. It is a sanity check, not a gate.
- **Trail check**: `npm run check:trail` (`factory/checks/trail.mjs`). Writes a `check` event named `trail`. Passes when the log is append-only against its git history, every row is well formed (no empty cell; a phase that is `start` or a lowercase slash path on the log's one tree), every row has a verdict whose pointers resolve (a `file:` pointer deleted since resolves at the commit that added its audit row, named in the evidence), and every audit has a non-Claude review. Rules about the real log live here, not in unit tests.
- **Manual run**: a check run with no `--run` and no `FACTORY_RUN` files its event under run `manual`.
- **Factory root**: the main checkout, never the cwd. Resolved from `--root`, then `FACTORY_ROOT`, then `CLAUDE_PROJECT_DIR`, then the repo holding `factory/log.mjs`. Subagents run in worktrees, but their events land in the main checkout.

## Fetch page

- **Fetch page**: `npm run fetch-page` (`node factory/fetch-page.mjs [--root <repo>] [--port 4174]`), served on `127.0.0.1` only. Lists each **open** `fetch.failed` ref: no later `artifact` event with that `ref` field or a path under `research/refs/<ref>/raw/`.
- **Title**: the `fetch.failed` event's optional `title` field, else the `title` column of `research/refs/catalog.tsv` (keyed by a `bibkey`, `key` or `ref` column), else none.
- **Drop**: `POST /drop?ref=<ref>&name=<file>` with the file as the body. Saved to `research/refs/<ref>/raw/<sanitized name>` (never overwriting), then an `artifact` event (`kind: ref`, `ref`) is written as agent `fetch-page` in the run of the `fetch.failed` event it closes. Refused: a ref with no open failure, a ref that isn't a plain folder name, a foreign `Host`, a cross-site `Origin`.

## Run id and agent id

- **Run id**: the orchestrator's Claude Code session id. Hooks take it from the payload's `session_id`. The orchestrator passes its own with `FACTORY_RUN` or `--run`.
- **Agent id**: Claude Code's `agent_id` from the hook payload. The orchestrator's is `orchestrator`. Hooks record `parent: "orchestrator"`, deliberately (issue #21). The payload has no parent field, and Claude Code fires `SubagentStart` and `SubagentStop` only for agents the orchestrator session spawns. An agent a subagent spawns gets no lifecycle events and no writer command, so it never appears in the stream. (Its parent is the `parentAgentId` in Claude Code's `subagents/agent-<id>.meta.json`, which is written after `SubagentStart` runs.)
- **Run marker**: `factory/run.json` in the factory root, `{"run": "<run-id>", "branch": "<integration branch>"}`. Gitignored local state. The orchestrator sets it when a run starts with `node factory/run-marker.mjs start --run <run-id> --branch <integration branch>` (run also from `FACTORY_RUN`) and clears it at the end with `node factory/run-marker.mjs stop`. A merge script reads the integration branch from it with `readMarker(root)`.
- **Orchestrated run**: a session whose id the run marker names. Only it is logged by the lifecycle hooks. With no marker, or a marker naming another run, a `SubagentStart`/`SubagentStop` writes nothing and injects no writer instructions, so meta sessions (reflect, review, close-outs) leave `factory/agents/` alone. A payload with no `session_id` is still recorded, under run `unknown`, while any run is marked.
- **Lifecycle hooks**: `.claude/settings.json` runs `factory/hooks/subagent.mjs` on `SubagentStart` and `SubagentStop` (they fire in the orchestrator session), during an orchestrated run only. It writes `agent.start` / `agent.stop`; a field the payload lacks becomes `unknown`. The stop `status` is the first `PASS`, `ISSUES` or `BLOCKED` in `last_assistant_message`. When that has none, the hook reads `agent_transcript_path` and uses the last `SubagentHandback` report, then the last assistant text block. If neither has one, the status is `unknown`. `agent.stop` carries only the contract's fields, `role` and `status`. The subagent's transcript is `<transcripts dir>/<run>/subagents/agent-<agent>.jsonl`, so the event doesn't name it. `agent.stop` events written before issue #21 also carry a `transcript` field with that path. The stream passes it through, but it isn't part of the contract, so the dashboard must not depend on it.
- **Writer command**: on `SubagentStart` the hook injects `additionalContext` telling the subagent its agent id, run id and the exact command for its own events:
  `node "<main>/factory/log.mjs" --root "<main>" --run <run-id> --agent <agent-id> <type> key=value ...`
